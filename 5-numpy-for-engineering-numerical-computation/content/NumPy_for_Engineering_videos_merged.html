Numpy Functions

Introduction

NumPy is more than a container for numbers: it ships with a large library of ready-made functions that do the heavy lifting of engineering computation. These fall into a few families you will use again and again: mathematical and arithmetic functions (element-wise addition, powers, exponentials, trigonometry), statistical functions (mean, median, standard deviation, min/max, sums along an axis), linear algebra functions in numpy.linalg (matrix multiplication, determinants, inverses, solving Ax = b, eigenvalues), array manipulation functions (reshape, transpose, concatenate, stack, split), sorting and searching functions (sort, argsort, argmax, where, searchsorted), and input/output functions for loading and saving data (loadtxt, genfromtxt, save, savetxt).

This matters in EGN3214 because engineering problems usually arrive as tables of measurements or systems of equations, not as single scalars. Writing Python loops over thousands of sensor readings is slow and error-prone; calling a vectorized NumPy function on the whole array is one line, far faster, and much closer to the mathematical notation you already use in statics, circuits, and thermodynamics.

As you watch the videos below, pay attention to three things: (1) the distinction between element-wise operations (the * operator) and true matrix operations (np.dot, the @ operator, or numpy.linalg routines) — this is the single most common source of bugs; (2) how shapes and axes control what a function returns, especially for statistics computed along rows versus columns; and (3) when a problem outgrows NumPy and is better handled by a specialized library such as SciPy. Keep a notebook open and retype the examples rather than only watching.

Introduction to NumPy and the ndarray

Introduction

NumPy (Numerical Python) is the foundation of almost all scientific and engineering computing in Python. At its core is a single data structure: the ndarray, an N-dimensional array of elements that all share one data type and sit in a contiguous block of memory. That design is what makes NumPy fast — operations are applied to whole arrays at once by compiled code rather than by stepping through items one at a time in Python.

In this course, NumPy is the bridge between the general-purpose Python you already know and real numerical engineering work: sensor data, measurement series, coordinate sets, matrices of coefficients, and simulation results. Before you can create arrays, index them, or do linear algebra, you need a clear mental model of how an ndarray differs from a Python list. A list can hold mixed types and grows easily, but it stores references to scattered objects; an ndarray is fixed in size and homogeneous, which is exactly what allows vectorized arithmetic and the attributes you will rely on throughout the module.

As you watch, focus on four things: what NumPy is and what problems it was built to solve; how an ndarray is created and what it actually stores; concrete comparisons of speed, memory, and behavior between arrays and lists (notice how + behaves differently for each); and the key attributes that describe an array — shape, ndim, size, and dtype. Try typing the examples yourself and printing those attributes for every array you make; it is the fastest way to build intuition for the rest of the module.

Creating NumPy Arrays

Introduction

Every NumPy workflow begins with getting data into an array. Sometimes that data already exists as a Python list or tuple and simply needs converting; more often, you need to generate it — a time vector for a simulation, a grid of sample points for plotting a function, a matrix of zeros to accumulate results, an identity matrix for a linear algebra step, or random values for a Monte Carlo trial. NumPy provides a dedicated creation function for each of these cases, and choosing the right one makes your code shorter, faster, and easier to read.

In this course, array creation is the foundation everything else rests on. The vectorized arithmetic, indexing, linear algebra, and statistics you will use later all assume you can produce arrays of the right shape and data type to begin with. Pay particular attention to the distinction between np.arange(), which is defined by a step size and excludes the endpoint, and np.linspace(), which is defined by a count of points and includes the endpoint — this difference causes a large share of beginner errors in engineering scripts.

As you watch, keep a few questions in mind: What arguments does each function take, and what does it return? What is the dtype of the resulting array, and when does that matter? How do the shape and reshape operations relate to the number of elements? Try typing each example into your own Python session and then changing one argument at a time to see what happens.

Element-Wise Operations and Universal Functions

Introduction

In NumPy, arithmetic and mathematical operations are applied element by element across an entire array at once. Writing a + b, a * 2, or np.sin(a) tells NumPy to loop internally in compiled code rather than in Python, which is why vectorized code is both shorter to write and dramatically faster than an equivalent for-loop. The functions that perform these element-wise operations — np.add, np.sqrt, np.exp, np.sin, and many others — are called universal functions, or ufuncs.

This matters for engineering work because measurement data, time steps, node positions, and sensor channels naturally live in arrays. Converting a column of readings from volts to pressure, computing the magnitude of force components, or evaluating a model at a thousand time points all become single expressions. Related ideas follow from the same mechanism: comparison operators (>, <=, ==) applied to an array return a Boolean array of the same shape, which can then be used as a mask, and aggregate reductions such as sum(), mean(), min(), max(), and std() collapse an array down to a summary value, optionally along a chosen axis.

As you watch, pay attention to three things: the shapes of the arrays going into each operation and coming out, when broadcasting lets arrays of different shapes combine (and when it raises an error), and the difference between an operation that returns a full array and a reduction that returns a single number. Try typing the examples yourself and checking .shape and .dtype after each step.

Broadcasting

Introduction

Broadcasting is the rule set NumPy uses to carry out arithmetic between arrays whose shapes are not identical but are compatible. Instead of forcing you to tile or copy data so that both operands have the same shape, NumPy conceptually stretches the smaller array along the dimensions where it has length 1 or where a dimension is missing. The result is code that looks like simple algebra — adding a scalar offset to a sensor array, subtracting a row of column means from a data matrix, or building a 2D grid from two 1D vectors — while running at compiled speed with no extra memory for the stretched copies.

In this course, broadcasting is what makes vectorized engineering computation practical. Once you can combine a (100, 3) array of measurements with a (3,) array of calibration constants, or a column vector of times with a row vector of frequencies, you stop writing nested Python loops and start writing expressions that mirror the equations in your textbook. Broadcasting is also the most common source of confusing bugs for new NumPy users, because a shape mismatch either raises an error or, worse, silently produces an array of the wrong shape.

As you watch, keep three things in the front of your mind. First, the actual rule: compare shapes from the trailing (rightmost) dimension backward, and dimensions are compatible only if they are equal or one of them is 1. Second, the role of reshaping tools such as reshape, np.newaxis, and None in deliberately creating a length-1 axis so that an operation broadcasts the way you intend. Third, how to read a ValueError about operands that could not be broadcast together, and how to use .shape to diagnose it before you run anything else.

Indexing, Slicing, and Fancy Indexing

Introduction

Once you can create NumPy arrays, the next essential skill is getting data back out of them. Indexing and slicing let you pull a single element, a row, a column, a sub-block, or a scattered set of values from an array. In engineering work this is how you isolate a sensor channel from a data matrix, trim a transient from the start of a time series, or grab every tenth sample from a long measurement record.

This topic moves from simple to advanced. Basic integer indexing uses positions (remember: counting starts at 0, and negative indices count from the end). Slicing uses the start:stop:step pattern and extends to multiple dimensions, such as A[1:4, 0:2]. Boolean (mask) indexing builds an array of True/False values from a condition and uses it to filter data, which is how you answer questions like "which readings exceeded the limit?" Fancy indexing passes an array or list of integers to select elements in any order, with repeats allowed. Finally, np.where gives you conditional selection: either the positions where a condition holds, or an element-wise choice between two values.

As you watch, pay close attention to three things: whether the result is a view into the original array or a copy (slices are views, fancy and Boolean indexing produce copies), how the shape of the result follows from the shape of the index, and how multi-dimensional indexing separates row and column specifications with a comma. Try every example in your own notebook and deliberately change the indices to see what breaks and why.

Reshaping, Transposing, and Array Manipulation

Introduction

Engineering data rarely arrives in the shape an algorithm expects. A sensor log may come in as one long 1-D stream when you need a table of rows and columns; a matrix may need to be transposed before it can be multiplied; results from several trials may need to be joined into one block, or split back apart. NumPy handles all of this through shape manipulation: operations that rearrange how the same underlying data is presented, usually without copying or changing a single value.

In this topic you will work with reshape to change dimensions, transpose (and the .T attribute) to swap axes, flatten and ravel to collapse an array back to one dimension, hstack/vstack/concatenate and the split functions to join and separate arrays, and techniques such as squeeze, np.newaxis, and expand_dims to add or remove length-one dimensions. These tools are the connective tissue between the array creation, indexing, and linear algebra skills covered elsewhere in this module.

As you watch, pay attention to three things: whether the total number of elements is preserved (reshape requires it), whether the result is a view sharing memory with the original or an independent copy (ravel versus flatten is the classic example), and which axis an operation acts along. Keep a Python session open and retype the examples with your own small arrays — shape errors are far easier to understand once you have caused a few deliberately.

Linear Algebra with NumPy

Introduction

Linear algebra is the mathematical backbone of most engineering computation. Circuit analysis, static equilibrium problems, finite element models, structural vibration, control systems, and least-squares curve fitting all reduce, at some point, to matrices and vectors. NumPy's numpy.linalg module gives you fast, well-tested implementations of these operations so you can focus on setting up the problem correctly rather than coding Gaussian elimination from scratch.

In this topic you will work with matrix multiplication (the @ operator, np.dot, np.matmul, and the related inner and outer products), solving systems of equations with np.linalg.solve, extracting eigenvalues and eigenvectors with np.linalg.eig, applying decompositions such as LU, QR, SVD, and Cholesky, and computing norms and determinants with np.linalg.norm and np.linalg.det. A recurring theme is the distinction between element-wise operations (the * operator) and true matrix operations (the @ operator) — a mistake here produces results that look plausible but are wrong.

As you watch, pay close attention to array shapes: which dimensions must match for a product to be legal, and what shape comes back. Also notice that results are floating point, so a determinant that should be exactly zero may come back as something like 1e-17; learn to interpret near-singular systems rather than trusting equality checks. Try to re-type the examples yourself as you watch, and then apply them to a small engineering system of your own.
