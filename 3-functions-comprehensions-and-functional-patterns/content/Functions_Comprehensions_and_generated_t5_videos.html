Introduction

Recursion is a problem-solving technique in which a function calls itself on a smaller version of the same problem. Instead of writing a loop that repeats work, you describe the problem in terms of itself: a factorial of n is n times the factorial of n-1, the nth Fibonacci number is the sum of the two before it, and so on. Every correct recursive function needs two parts: a base case that stops the chain of calls and returns a direct answer, and a recursive case that moves the input closer to that base case.

This topic matters in EGN3214 because recursion is a natural fit for problems with nested or self-similar structure, and because writing it forces you to think carefully about what a function returns and how parameters change between calls. It also connects to how Python actually runs your code: each call occupies a frame on the call stack, so recursion that never reaches a base case, or that goes too deep, raises a RecursionError rather than running forever.

As you watch, keep three questions in mind for every example: What is the base case? How does the recursive case shrink the input? What would happen if the base case were missing or wrong? It is also worth noting where the videos compare recursion to an iterative loop, since in Python an equivalent loop is often faster and uses less memory even when recursion reads more clearly.
