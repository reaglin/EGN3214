Introduction

When you define a function, the names listed in the parentheses of the def line are its parameters. When you call that function, the values you supply are its arguments. Keeping those two words straight makes it far easier to read error messages, documentation, and your own code, so this topic starts there and then builds outward to the different ways arguments can be matched to parameters.

Python gives you several options. Positional arguments are matched in order, left to right, so the order you write them matters. Keyword arguments are matched by name, which makes calls more readable and lets you skip the order entirely. Default parameter values let you declare a fallback in the function definition so callers can leave some arguments out, which is how most real-world library functions offer optional behavior.

As you watch these videos, pay attention to three things: the exact rule for where positional arguments must appear relative to keyword arguments, what happens when you pass too few or too many arguments, and how a default value changes which arguments are required. Try retyping each example in your own editor and then deliberately break it — swap the order, misspell a keyword, omit a required argument — so you learn to recognize the resulting TypeError messages.
