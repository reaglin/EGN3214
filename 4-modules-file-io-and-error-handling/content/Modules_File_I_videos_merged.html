Introduction to Python Modules

Introduction

A module is simply a Python file containing code — functions, classes, and variables — that you can reuse in other programs. Instead of rewriting the same square-root routine or random-number generator in every project, you import a module and call what you need. Python ships with a large standard library of modules such as math, random, os, and sys, and you can also write your own modules and install third-party ones with pip.

In this course, modules matter because they are the bridge between writing short scripts and building organized, maintainable engineering programs. The same import mechanics you learn here are what let you later open files, catch errors, and eventually pull in scientific packages. Understanding how Python finds a module at runtime — the module search path — also saves you hours of debugging the all-too-common ModuleNotFoundError.

As you watch, pay attention to the differences among the import forms: plain import module, selective from module import name, and aliasing with import module as alias. Notice how each form changes the name you actually type when calling a function, and watch for any discussion of where Python looks for files (the current directory, then installed library locations). Try typing each example yourself in a file rather than only in the interactive shell, since that is where search-path behavior becomes visible.

Writing and Using Custom Modules

Introduction

Up to now you have probably written each program as a single Python file. As your engineering scripts grow, you will find yourself copying the same unit-conversion function, material constant, or plotting helper from one file to the next. A custom module solves this: any .py file you write can be imported into another script, so the functions and constants you define once become reusable tools across every project you build.

This topic walks through the full workflow. You create a module file with a sensible name, group related functions and constants inside it, add docstrings so others (including future you) know how to use it, and then import it from another script using import or from ... import. A key piece is the if __name__ == '__main__' guard, which lets a file behave as both a runnable program and an importable library: code under the guard runs only when you execute the file directly, not when something imports it. Without the guard, your module's test or demo code fires every time it is imported, which is a common and confusing bug.

The videos below focus on the two parts that trip students up most: understanding what __name__ actually is and why the guard matters, and organizing code sensibly across files. While watching, pay attention to what gets printed when a file is run directly versus imported, how module-level code differs from code inside functions, and how splitting code into separate files changes the way you call it.

Using Standard Library Modules

Introduction

Python ships with a large collection of ready-made modules known as the standard library. Instead of writing your own code to compute a square root, list the files in a folder, read command-line arguments, stamp a record with the current date, or generate a test value, you import a module that already does it. In this topic we look at five that come up constantly in engineering scripting: math for numeric functions and constants, os and os.path for working with files and directories in a platform-independent way, sys for interacting with the interpreter and the command line, datetime for dates and times, and random for pseudo-random values and sampling.

These modules matter in EGN3214 because they are the bridge between the plain Python syntax you have practiced and real scripting tasks: building a path to a data file, checking whether it exists before opening it, timestamping output, pulling an input filename from the command line, and exiting cleanly when something goes wrong. None of them require installation, so any script you write using them will run on a classmate's machine or a lab computer without extra setup. They also pair directly with the file I/O and exception handling material in the rest of this module.

As you watch the videos below, pay attention to three things: the import statement itself and the different forms it can take, the dotted notation used to reach a function inside a module, and how the presenter finds out what a module offers. Getting comfortable reading the official Python documentation for a module is more valuable than memorizing individual function names, because the same pattern applies to every module in the standard library.

File I/O with the with Statement

Introduction

Up to now your programs have worked with data that lives only in memory: once the script ends, everything is gone. File input and output (file I/O) is how a program keeps data between runs — reading a configuration file, logging sensor readings, saving results to a text file that a colleague can open later. In Python the starting point is the built-in open() function, which takes a filename and a mode such as 'r' for reading, 'w' for writing (which overwrites), or 'a' for appending.

The catch is that an open file is a limited operating-system resource, and if your program crashes before closing it you can leak file handles or lose buffered data that was never written to disk. That is why Python offers the with statement, a context manager that automatically closes the file when the block ends — even if an exception is raised inside it. This connects directly to the error-handling material in this module: a with block paired with try/except is the standard, professional way to work with files. You should also get comfortable with pathlib, the modern object-oriented way to build and inspect file paths so your code works on Windows, macOS, and Linux without hard-coded slashes.

As you watch the videos below, pay attention to three things: the exact syntax of the with open(...) as f: line and what the variable f actually is; which methods are used to pull text out of a file (read, readline, readlines, or looping over the file directly); and how paths are constructed and checked before a file is opened. Try typing each example yourself and then deliberately break it — use a filename that does not exist — so you can see what error Python raises and how the with statement still cleans up.

Reading and Writing CSV Files

Introduction

A CSV (comma-separated values) file is one of the simplest and most widely used ways to store tabular data. It is just plain text: each line is a row, and the values in that row are separated by commas. Spreadsheet programs, lab instruments, sensors, and web services all export CSV, which is why engineers run into it constantly. Because it is plain text, you can open a CSV in any editor and see exactly what is there — a useful habit before you write code against it.

Python ships with a built-in csv module, so no third-party installation is required. In this topic you will work with four tools from that module: csv.reader, which gives you each row as a list; csv.DictReader, which uses the header row to give you each row as a dictionary keyed by column name; csv.writer, which writes rows from lists; and csv.DictWriter, which writes rows from dictionaries and can emit the header for you. This connects directly to the file I/O and exception handling work earlier in Module 4 — you still open files with open(), still use with blocks, and still need to handle missing files and malformed data.

As you watch, pay attention to a few specific things: how the file is opened (including the newline='' argument that prevents blank rows on some systems), whether the header row is being consumed or skipped, and when the list-based approach is more convenient than the dictionary-based one. Also notice that everything read from a CSV arrives as a string, so numeric columns must be converted with int() or float() before you can do arithmetic on them.

Working with JSON

Introduction

JSON (JavaScript Object Notation) is a lightweight, text-based format for representing structured data. It looks a lot like a mix of Python dictionaries and lists: curly braces hold key-value pairs, square brackets hold ordered sequences, and values can be strings, numbers, booleans, null, or nested objects and arrays. Because it is both human-readable and easy for programs to parse, JSON has become the default way that web APIs exchange data and that applications store settings and configuration.

In this module you have been working with files and with code that can fail at runtime; JSON sits right at the intersection of those ideas. Python's built-in json module gives you four functions to remember: json.loads and json.load turn JSON text (from a string or a file object) into Python objects, and json.dumps and json.dump turn Python objects back into JSON text (to a string or a file). You will also meet the module's limits — not every Python object is serializable, dictionary keys become strings, tuples become arrays, and malformed input raises a JSONDecodeError that your program should handle gracefully.

As you watch the videos below, pay attention to three things: the mapping between JSON types and Python types, the difference between the functions ending in 's' (string) and those without (file), and formatting options such as indent and sort_keys that make configuration files readable. Try typing the examples yourself and then deliberately break one — delete a comma or a quote — so you can see what error Python reports.

Error Handling with try-except

Introduction

Up to this point, most of your Python scripts have assumed everything goes right: the file exists, the user types a number, and the denominator is never zero. Real engineering scripts do not get that luxury. A sensor log may be missing, a CSV column may contain text where a float was expected, or a calculation may divide by zero partway through a batch of data. Python signals these runtime problems by raising exceptions, and if nothing handles them, the program stops immediately with a traceback.

Exception handling gives you a structured way to anticipate those failures and respond to them. In this topic you will learn what an exception actually is, how the basic try-except block separates risky code from recovery code, and how the optional else and finally clauses let you run code only when no error occurred or always run cleanup such as closing a file. You will also see how to capture the exception object itself so you can report a useful message instead of a bare crash, and how to raise exceptions deliberately when your own function receives invalid input, such as a negative length or an out-of-range temperature.

As you watch the videos below, pay attention to three things: which specific exception types are being caught (catching a bare Exception hides bugs), the exact order in which try, except, else, and finally execute, and how the presenter uses the exception message to explain what went wrong. Then connect it back to Module 4 as a whole, since file I/O is where most of your exception handling will live, and try the same examples yourself with deliberately broken input.
