Introduction

Up to this point, most of your Python scripts have assumed everything goes right: the file exists, the user types a number, and the denominator is never zero. Real engineering scripts do not get that luxury. A sensor log may be missing, a CSV column may contain text where a float was expected, or a calculation may divide by zero partway through a batch of data. Python signals these runtime problems by raising exceptions, and if nothing handles them, the program stops immediately with a traceback.

Exception handling gives you a structured way to anticipate those failures and respond to them. In this topic you will learn what an exception actually is, how the basic try-except block separates risky code from recovery code, and how the optional else and finally clauses let you run code only when no error occurred or always run cleanup such as closing a file. You will also see how to capture the exception object itself so you can report a useful message instead of a bare crash, and how to raise exceptions deliberately when your own function receives invalid input, such as a negative length or an out-of-range temperature.

As you watch the videos below, pay attention to three things: which specific exception types are being caught (catching a bare Exception hides bugs), the exact order in which try, except, else, and finally execute, and how the presenter uses the exception message to explain what went wrong. Then connect it back to Module 4 as a whole, since file I/O is where most of your exception handling will live, and try the same examples yourself with deliberately broken input.
