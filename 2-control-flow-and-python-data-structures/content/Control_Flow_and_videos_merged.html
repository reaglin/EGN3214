Conditional Statements

Introduction

Up to this point your programs have run straight through from the first line to the last. Conditional statements change that: they let a program examine a value, ask a yes-or-no question about it, and then choose which block of code to run. In Python this is done with the if statement, optionally extended by one or more elif clauses for additional cases and a final else clause that catches everything not already handled.

The questions themselves are built from comparison operators (==, !=, <, >, <=, >=) and logical operators (and, or, not), which combine simple tests into more complex ones. Because Python uses indentation to mark the body of a conditional, you also need to be careful about how blocks are nested — a conditional placed inside another conditional only gets evaluated when the outer condition is true. This matters in engineering work, where decisions such as whether a measurement is in tolerance, which material a stress value calls for, or whether a sensor reading is an alarm condition all depend on branching logic.

As you watch, pay attention to three things: the exact syntax (the colon at the end of the condition line and the consistent indentation beneath it), the order in which branches are tested, and the fact that in an if/elif/else chain only one branch ever runs. Try pausing the videos and predicting the output before the instructor shows it — tracing execution by hand is the fastest way to build reliable intuition.

for Loops and the range() Function

Introduction

Repetition is one of the core ideas in programming. Rather than writing the same calculation twenty times, you write it once inside a loop and let Python repeat it. The for loop is Python's tool for stepping through a sequence of items one at a time — characters in a string, measurements in a list, or numbers produced by the range() function. In engineering work, that sequence is often a set of sensor readings, a table of material properties, or a span of time steps in a simulation.

The range() function deserves special attention because it is how you turn a for loop into a counted loop. range(stop), range(start, stop), and range(start, stop, step) each generate a sequence of integers, and the fact that the stop value is excluded is a common source of off-by-one errors. When you need both the position and the value of each item — for example, to report that the third reading exceeded a limit — enumerate() gives you the index and the element together, which is cleaner and less error-prone than manually maintaining a counter variable.

As you watch these videos, trace the loop variable by hand: write down its value on each pass and note exactly when the loop stops. Pay attention to indentation, since the indented block is what repeats. Also notice how each presenter chooses between looping directly over a collection and looping over range() — knowing which to reach for is a skill you will use throughout this course.

while Loops

Introduction

A while loop repeats a block of code as long as a condition evaluates to True. Unlike a for loop, which walks through a known sequence or range, a while loop is the right tool when you cannot say in advance how many repetitions are needed — reading sensor values until a threshold is crossed, asking a user for input until it is valid, or refining a numerical estimate until the error is small enough.

Three ideas hold this topic together. First, the structure: initialize a variable before the loop, test a condition at the top, and update that variable inside the loop body. Second, loop guards: if the condition never becomes False, you get an infinite loop, which is the most common while-loop bug. Third, the comparison with for loops: many loops can be written either way, and recognizing when each is clearer is part of writing readable engineering code.

As you watch, trace the loop variable by hand on each pass — what is its value when the condition is tested, and what changes it inside the body? Pay particular attention to where the update statement sits; moving or forgetting it is usually what turns a working loop into one that never stops.

Loop Control: break and continue

Introduction

Loops repeat work, but real programs rarely want every iteration to run to completion in exactly the same way. Sometimes you find what you were searching for and want to stop immediately; sometimes you hit a bad or irrelevant data point and want to skip just that pass and keep going. Python gives you two small but powerful keywords for this: break, which exits the loop entirely, and continue, which jumps straight to the next iteration.

This topic also introduces a feature that surprises many newcomers: the else clause attached to a for or while loop. Unlike the else in an if statement, a loop's else block runs only when the loop finishes normally, that is, without ever hitting a break. That makes it a clean way to express search patterns such as "look through all the readings; if none exceeded the threshold, report that everything was within limits." You will also encounter pass, which does nothing and is simply a placeholder, and it is worth keeping it mentally separate from break and continue.

As you watch, pay attention to three things. First, trace exactly where control goes after break versus after continue, especially inside nested loops, where break only exits the innermost loop. Second, watch how the loop variable and any counters or accumulators behave when an iteration is skipped, since a continue placed before an increment in a while loop is a classic infinite loop bug. Third, notice when break and continue genuinely make code clearer and when a well-written condition would be simpler and more readable.

Lists

Introduction

A list is Python's workhorse container: an ordered, mutable sequence that can hold numbers, strings, or even other lists. Because the items keep their order, you can reach any element by its index position, and because lists are mutable, you can change, add, or remove items after the list has been created. In engineering work this maps naturally onto things like a series of sensor readings, a set of measured dimensions, or a queue of simulation results.

In this course, lists are the bridge between the control flow ideas you just met and the data structures that follow. Loops become far more useful once you have a collection to iterate over, and conditional statements become more powerful once you can filter or update the contents of a list. Later in the module you will compare lists against tuples, dictionaries, and sets, so a solid grasp of list behavior gives you the baseline for those comparisons.

As you watch, pay attention to five things: how a list is created and indexed (including negative indices), how items are changed or removed in place, how slice notation selects a sub-range, how a list comprehension compresses a loop into a single expression, and what the common built-in methods such as append, insert, remove, pop, sort, and reverse actually do to the original list. Try typing each example yourself and then changing one value to see what happens.

Tuples

Introduction

A tuple is an ordered sequence of values written with parentheses, such as (3.5, 2.1, 0.0) or ('steel', 200e9). Like a list, a tuple keeps its items in order and lets you reach them by index or slice. Unlike a list, a tuple is immutable: once it is created, you cannot add, remove, or replace its elements. That single difference is what makes tuples useful for fixed collections — sensor coordinates, RGB color values, material constants, or a pair of values returned together from a function.

In this course, tuples matter for two reasons. First, they are the natural choice whenever data should be protected from accidental modification, which makes engineering code easier to trust and to read. Second, tuples support packing and unpacking, a convenient Python idiom that lets you assign several variables at once (x, y, z = point) and return multiple results from a single function. You will also meet tuples indirectly in loops, in dictionary keys, and in function arguments, so recognizing them early pays off later.

As you watch, pay attention to three things: the syntax details that trip people up (especially the single-element tuple, which needs a trailing comma), what happens when you try to modify a tuple and what the error message tells you, and which operations are still allowed — indexing, slicing, concatenation, membership tests, count, and index. Finally, keep a running mental list of decision criteria: when is a tuple the better choice than a list, and when does immutability get in your way?

Dictionaries

Introduction

A dictionary is a Python collection that stores data as key-value pairs. Instead of asking for "the item at position 3," you ask for "the value stored under the key 'voltage'." You create dictionaries with curly braces, access values by key, and add, update, or remove entries as your program runs. Because keys are looked up directly rather than by scanning through positions, dictionaries give fast access even when they hold large amounts of data.

This matters in EGN3214 because most engineering data is labeled, not just ordered. Sensor readings tied to sensor IDs, material properties tied to material names, unit conversion factors tied to unit symbols, and student records tied to ID numbers all map naturally onto key-value pairs. Learning dictionaries also sharpens your ability to choose among lists, tuples, dictionaries, and sets, which is one of the central skills of this module.

As you watch, pay attention to four things: the syntax for creating a dictionary and retrieving a value by key, what happens when you assign to a key that does or does not already exist, the methods keys(), values(), and items() and how they drive loops over a dictionary, and the rules about what can serve as a key. Try each example in your own Python environment and deliberately trigger a KeyError so you recognize it later.

Sets and Choosing the Right Data Structure

Introduction

A set in Python is an unordered collection of unique elements. Unlike a list, a set cannot contain duplicates and does not preserve a fixed order, so you cannot index into it. What you gain in return is speed and expressiveness: checking whether a value is in a set is very fast even for large collections, and sets support mathematical operations such as union, intersection, difference, and symmetric difference directly with operators or methods.

In engineering work these properties matter more than they might first appear. Removing duplicate sensor IDs, finding which parts appear in two different bills of materials, checking whether a node has already been visited in a graph traversal, or testing membership against a large lookup table are all tasks where a set is the natural and efficient choice. Python also provides frozenset, an immutable version of a set that can itself be used as a dictionary key or placed inside another set.

This topic closes Module 2 by bringing lists, tuples, dictionaries, and sets together and asking the practical question: which one should you use? As you watch, pay attention to three things — the syntax for creating sets (and the trap that empty curly braces create a dictionary, not a set), what each set operation returns and whether it modifies the original set, and the trade-offs in mutability, ordering, duplicates, and lookup speed that distinguish the four core structures.
